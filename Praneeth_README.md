What surprised you most about how the widget tree, state, or lifecycle actually behaves once you saw it applied in the app?
ANS:-
What surprised me most was seeing how the widgets are connected like a tree. Changing the state can cause the build method to run again and update the UI. I also learned that the controller needs to be disposed of when it is no longer needed.

Which concept (Widget Tree, Stateless vs. Stateful, Controllers & Lifecycle, or Declarative UI) took the longest to click for you, and what finally made it make sense?
ANS:-
Declarative UI took the longest for me to understand. It made more sense when I saw that setState() tells Flutter that something changed, and then build() creates the updated UI based on the new state.

What part of the GitHub workflow (repo setup, cloning, committing, pull requests) felt least familiar, and how did you work through it?
ANS:-
Pull requests and branches felt least familiar to me. I worked through it by creating my own branch, committing my changes, pushing the branch to GitHub, and then creating a pull request. Following the steps one at a time helped me understand the process.

If you rebuilt this activity from scratch tomorrow, what would you do differently?
ANS:-
If I rebuilt this activity tomorrow, I would set up the GitHub repository and branch first. I would also make smaller commits as I worked instead of waiting until the end. This would make it easier to find and fix problems.
